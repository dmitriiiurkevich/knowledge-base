
книги, статьи, сообщения форумов, код,... → обучающая выборка → LLM

prompt → LLM → completion

Когда модель получает prompt, совпадающий с фрагментом документа из обучающей выборки, она статистически тяготеет к тому, чтобы вtрнуть completion, являющийся наиболее вероятным продолжением этого фрагмента.

Пример

Промпт: *The capital of France is*

LLM не знает географию. LLM знает, что в миллионах документов из её обучающей выборки после этих слов стояло слово Paris. Поэтому LLM продолжит этот промпт словом Paris.

LLM не «думает» в человеческом смысле — она продолжает текст.

Стиль и формат промпта влияет на ответ, потому что задаёт «тип документа» — если промпт похож на учебник, ответ будет академическим; если на чат — разговорным

### LLM vs search index

Раньше для решения аналогичной задачи в традиционном поисковом движке / search engine (таком как Google, Elasticsearch,...) применялась специальная структура данных — поисковый индекс / search index.

Как это работает?

Этап 1 
Сбор данных — специальный скрипт — crawler — обходит документы или страницы.


Этап 2
Токенизация — текст документов или страниц разбивается на токены.

Этап 3
Построение инвертированного индекса
- word1 / token1 → doc1, doc7, doc42,...
- word2 / token2 → doc7, doc15,...
- word3 / token3 → doc3, doc15, doc88,...
- ...

Приступая к обработке поискового запроса, search engine не начинал полный перебор по всем документам, а использовал этот индекс.

LLM решает во многом схожую задачу релевантного поиска, но совершенно другими методами. 

Принцип работы традиционного search engine требует, чтобы все проиндексированные документы хранились бы явно, а построенный search index использовался бы в качестве указателя.

LLM не хранит документы вообще. Вся информация, извлечённая из обучающей выборки, растворяется в миллиардах весов нейронной сети.


| Search engine                         | LLM                                                                                                |
| ------------------------------------- | -------------------------------------------------------------------------------------------------- |
| явные указатели                       | неявные веса                                                                                       |
| поиск совпадений, точных или нечётких | поиск семантического сходства                                                                      |
| результат чаще детерминирован         | результат чаще стохастичен                                                                         |
| хорошо находит релевантные фрагменты  | хорошо синтезирует релевантные фрагменты<br>(настолько хорошо, что может отвечать связным текстом) |

RAG — Retrieval-Augmented Generation — генерация с расширенными возможностями поиска — комбинация  search index и LLM.

LLM тоже может использовать для генерации completion механически заученные последовательности токенов. Это называется дефектом переобучения / overfitting нейронной сети.

Язык людей отражает реальность. Язык моделей отражает людей.

Если вы начали подозревать, что LLM галлюцинирует, запросите дополнительный контекст, он облегчит вам проверку.

Truth bias — искажение, которое возникает в следствие того, что модель пытается «верить» в истинность промпта, даже если промпт содержит ошибки.

Излишне сложный промпт: *Представь себе, что сейчас 2030-й год и неандертальцев воскресили*

Лучше так: Сейчас *2031-й год, и уже год как неандертальцев воскресили*


Токенизатор — это четыре элемента:
- $\Sigma$ — базовый алфавит — байты или код-поиты Unicode
- $V$ — словарь модели — его элементы называются токенами
- $enc: \Sigma^* \to V^*$
- $dec: V^* \to \Sigma^*$ — две взаимо-обратные функции: $dec(enc(s))=s$


Токен — это элемент $V$ — символ выходного алфавита функции $enc$.

Забегая вперёд, дадим более формальное определение: токен с индексом $i$ — это строка $E[i]$ матрицы эмбеддингов, задающей авторегрессионное распределение модели. 

Разные модели будут по-разному токенизировать один и тот же текст.

Одна и та же модель будет по-разному токенизировать текст на разных языках, код, числовые данные,...

Обычно один токен — это одна морфема. 

Однако, в зависимости от особенностей конкретной модели, токен может быть и целым словом. Например, названия стран для токенизатора ChatGPT являются отдельными токенами. 

Обычно эмодзи — это два токена. Иероглиф — несколько токенов.

Слово, написанное заглавными буквами, будет не так, как то же самое слово, но написанное строчными буквами.

Важно понимать, что после токенизации строка преобразуется в список чисел, и дальше модель работает только с этими числами.

Плохой практикой будет использование промптов типа: *Бывают ли европейские страны, начинающиеся на "Ш"?*

Модель запросто может ответить, что таких стран нет, или согласиться с тем, что Франция начинается на Ш.

Модель видит только номера токенов, но не имеет ни малейшего понятия о том, какие конкретно символы скрываются за этими номерами.

Хорошей практикой будет сначала попросить модель составить вам список всех европейских стран, а потом отфильтровать нужные, используя синтаксическую логику.

Время, за которое модель прочитает промпт, пропорционально количеству токенов в промпте. Время, за которое модель даст ответ, пропорционально количеству токенов в ответе.

Цикл работы авторегрессионной LLM:
- На основании токенизированного промпта генерируем один токен.
- Добавляем только что сгенерированный токен в конец токенизированного промпта.
- Повторяем цикл до тех пор, пока не будет сгенерирован специальный EOS-token — end of sequence token. 

Процесс выбора единственного токена из списка возможных называется sampling.

Обычно список возможных токенов включает в себя вообще все токены алфавита $V$.

Для каждого токена алфавита $V$ LLM вычисляет вероятность — обычно, логарифмическую вероятность или $logbrob$ — того, что именно этот токен должен быть выбран для продолжения промпта.
